# Трекер находок: GitHub Issues + Projects

Дата: 2026-10-15. Статус: **реализовано**. Владелец темы: этот документ.

Область: **только процесс учёта находок** — метки, шаблоны, доска, правила
разграничения с `docs/`. Код приложения, бэкенд и CI здесь не меняются.

---

## 1. Задача

Сейчас записать найденный дефект или идею некуда. GitHub Issues в репозитории
включены, но за всю историю проекта не заведено ни одной (`open_issues: 0`).
Всё открытое живёт в трёх местах, ни одно из которых не является списком:

| Где оседает | Почему не работает |
|---|---|
| Переписка с ИИ в разных сессиях | История не общая, найти «что мы там решили» нельзя |
| Память агента (`memory/`) | Только то, что агент счёл нужным запомнить; это не список задач |
| `docs/superpowers/plans/` | Задания на **уже спроектированное**; сырая находка туда не влезает |

Отдельная боль — **находки с телефона**. Приложение установлено на устройстве,
дефект виден там же, но записать его негде: под рукой нет ни редактора, ни
терминала, и к следующему дню детали теряются.

Цель: **одно место, куда находка попадает за секунды с телефона и остаётся
видимой до закрытия**, с приоритетами и разбивкой по платформам.

## 2. Принятые решения

| # | Решение |
|---|---|
| 1 | Трекер — **GitHub Issues** в существующем репозитории. Новых сервисов и ключей нет |
| 2 | Доска — **GitHub Projects** (Канбан по Status), поля Priority и Area. Создана вручную через браузер — MCP не умеет Projects v2 |
| 3 | Захват с телефона — **приложение GitHub** и **чат с агентом**. Веб-ярлык отклонён |
| 4 | Метки по трём осям: **тип + область + приоритет** |
| 5 | Issue публичны; доска — **приватная**. Правило «без чувствительных деталей» в issue действует |
| 6 | Issue = **только сырьё**. Проработанная тема уезжает в `docs/superpowers/specs/`, issue закрывается ссылкой |

## 3. Что сделано

| Что | Состояние |
|---|---|
| Метки | **11 заведено**: `feature`, `idea`, `task`, `android`, `ios`, `backend`, `docs`, `infra`, `P0`, `P1`, `P2` (плюс дефолтная `bug`) |
| Дубли меток | `enhancement` и `documentation` **удалены** — дублировали `feature` и `docs` |
| Шаблоны | `.github/ISSUE_TEMPLATE/`: `bug.yml` (метка `bug` сама), `idea.yml` (метка `idea` сама), `config.yml` (пустые issue выключены) |
| Доска | «Трекер находок», **приватная**, привязана к `vpn-app-design` |
| Колонки | Inbox → Разобрано → В работе → Готово |
| Поля доски | Priority (`P0`/`P1`/`P2`), Area (`android`/`ios`/`backend`/`docs`/`infra`) |
| Начальные записи | #1 киллсвитч, #2 лицензия, #3 статус ≠ защищено. Все в колонке Inbox |
| Workflow auto-add | включён, фильтр на `vpn-app-design` |

Проверено в браузере: шаблон «Баг» проставляет метку `bug` без выбора, шаблон
«Идея» — `idea`; доска открывается в режиме Board с четырьмя колонками и тремя
записями.

**Доска оказалась приватной** — GitHub делает проекты аккаунта приватными по
умолчанию. Это строже, чем требовало решение №5: публичны только issue, сама
доска с приоритетами и статусами видна владельцу. Менять не нужно.

## 4. Разметка

Три независимые оси. Одна запись несёт ровно одну метку типа, одну области и
одну приоритета.

| Ось | Метки | Цвет |
|---|---|---|
| Тип | `bug`, `feature`, `idea`, `task` | красный, зелёный, сиреневый, голубой |
| Область | `android`, `ios`, `backend`, `docs`, `infra` | нейтральные |
| Приоритет | `P0`, `P1`, `P2` | тёмно-красный, оранжевый, серый |

Смысл приоритетов:

- **P0** — приложением нельзя пользоваться: не подключается, роняет, теряет
  оплаченный доступ.
- **P1** — работает, но мешает: регулярный сбой, раздражающее поведение,
  заметная дыра в защите.
- **P2** — всё остальное, включая идеи.

Статус в метках **не дублируется** — он живёт в поле доски. Метки статуса
(`in progress` и подобные) не заводим: это второй источник правды.

## 5. Доска Projects

Поля:

| Поле | Значения |
|---|---|
| Status | `Inbox` → `Разобрано` → `В работе` → `Готово` |
| Priority | `P0`, `P1`, `P2` (дублирует метку — видно в таблице без открытия issue) |
| Area | `android`, `ios`, `backend`, `docs`, `infra` |

Колонка **Inbox** — точка входа. Всё, что создано с телефона, падает туда
неразобранным: без области и приоритета. Разбор — отдельное действие, когда есть
время, а не часть захвата.

`Status` живёт в доске, `Priority` и `Area` дублируют метки — чтобы читать доску
не открывая issue. Источник правды для обоих — метки; если поле и метка
разойдутся, верна метка.

Доска создаётся **вручную в веб-интерфейсе** (`Projects` → `New project` →
`Board`). Причина: GitHub MCP не предоставляет инструментов Projects v2, поэтому
автоматизировать её создание агент не может. Метки, шаблоны и issue агент
заводит сам.

## 6. Шаблоны

Файлы в `.github/ISSUE_TEMPLATE/`. Ключевая хитрость: шаблон **проставляет
метку типа сам**, из собственного frontmatter. На телефоне не нужно выбирать
ничего в списках — только печатать текст.

**`bug.yml`** — метка `bug` автоматически. Поля:

1. Что случилось — свободный текст, обязательно.
2. Как повторить — свободный текст, необязательно.
3. Версия приложения — необязательно.

**`idea.yml`** — метка `idea` автоматически. Поля:

1. Что хочется и зачем — свободный текст, обязательно.
2. Область — необязательно, из готового списка.

**`config.yml`** — пустые issue выключаю (`blank_issues_enabled: false`), чтобы
каждая запись приходила размеченной хотя бы типом.

Область и приоритет в шаблон **не** выношу: это работа разбора, когда уже видно,
во что запись превращается. Иначе телефонный захват перестаёт быть «три тапа».

## 7. Правило публичности

Репозиторий публичный, issue видны всем и индексируются. В `issue` **не попадает**:

- IP-адреса серверов и имена хостов (`194.87.252.181`, любые домены раздачи);
- ключи, токены, содержимое `.ovpn`, PEM-блоки;
- детали, из которых читается, что именно и как обходится, — устройство обходов
  описывается только по признаку («список РФ-сервисов не применяется»), без
  перечисления маршрутов;
- адреса и данные клиентов.

Допустимо: идентификаторы версий, номера строк, имена классов и функций, текст
ошибок ядра, обезличенное описание поведения. Всё это уже лежит в открытом
репозитории и секрета не составляет.

Формулировка от обратного: **если деталь нельзя положить в коммит публичного
репозитория — её нельзя и в issue.** Правило простое, потому что в проекте уже
действует ровно такая дисциплина для `.ovpn` и логов.

## 8. Разграничение с `docs/`

Два списка не должны конкурировать. Правило:

```
находка ──► issue ──(проработка)──► docs/superpowers/specs/ + plans/ ──► issue закрыт ссылкой
   сырьё        разбор                      проект                    след остаётся
```

| Состояние темы | Где живёт | Что в issue |
|---|---|---|
| Сырая находка, «надо разобраться» | issue | сам текст находки |
| Идёт проектирование | issue + спека | ссылка на спеку в работе |
| Спроектировано, есть план | `docs/superpowers/plans/` | **закрывается** со ссылкой |
| Работа сделана | код + тесты | закрыт |

Issue **никогда не дублирует** содержание спеки. Он держит ссылку. Так у проекта
остаётся один владелец темы (правило из `CLAUDE.md`) и один актуальный список
открытого.

## 9. Как этим пользуется агент

**Пишет** — когда при работе находит дефект или идею за пределами текущей задачи.
Issue и есть отчёт: отдельным абзацем в ответе он не пересказывается (совпадает
с действующим правилом «не пересказывать побочные находки»).

**Читает** — когда вопрос касается открытого: «что там открыто», «запиши баг»,
«что с обходами». Поиск через MCP по меткам, например `label:bug label:android`
или `label:P0`.

**Разбирает** — по просьбе: проставляет область и приоритет, переносит карточку
из `Inbox` в `Разобрано`. Перенос колонки и поля проекта агент сделать **не
может** — MCP не умеет Projects v2; эту часть владелец делает в вебе.

Границы: агент не создаёт и не настраивает доску, не меняет чужие issue, не
закрывает issue без основания.

## 10. Начальный состав

Заведено то, что **уже известно и лежит без дела** — не выдуманное ради примера:

| # | Запись | Метки |
|---|---|---|
| 1 | Киллсвитча нет: при разрыве туннеля трафик уходит напрямую | `idea`, `android`, `P1` |
| 2 | Лицензия: GPLv2 в `LICENSE` не следует из состава кода | `task`, `docs`, `P2` |
| 3 | Статус не отличает «подключено» от «защищено»: щупа нет | `idea`, `android`, `P1` |

Все три — в колонке Inbox. Массово переносить историю из `docs/` **не нужно** —
проработанное там и должно остаться.

## 11. Что НЕ делаем

- Не заводим milestone'ы и релизные вехи — пока нет релизного цикла, который бы
  их требовал.
- Не переносим в issue историю из `docs/superpowers/`.
- Не автоматизируем создание issue из кода (TODO-парсеры и подобное) — находки
  на то и находки, что их замечает человек или агент.
- Не добавляем метки статуса — статус только в доске.
