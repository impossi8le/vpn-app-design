# Журнал проверок сессии 2026-10-07

Сессия по релизу `android-v102`. Ниже — по каждому утверждению: **чем
проверено, как и на чём**. Отдельным списком — что осталось **не проверено**.
Без округления в свою пользу: непроверенное помечено непроверенным.

Телефон — Samsung SM-S928B, Android 16. Сервер —
`https://194-87-252-181.sslip.io:4443`.

## Проверено на живом телефоне (Samsung SM-S928B, Android 16)

- **Обновление из самого приложения доходит до конца.** Наблюдали прогресс
  `4% → 26% → 52% → 79%`, затем системный установщик, затем установленную
  версию: сначала v98, потом v101, потом v102. Симптом прежнего срыва (см.
  «`callTimeout` обрывает закачку» в `architecture/2026-10-06-app-update.md`)
  больше не воспроизводится.
- **Карточка уведомления появляется.** После запроса разрешения `POST_NOTIFICATIONS`
  в рантайме шторка показывает «VPN — Подключено» (раньше на Android 13+
  карточка молча не показывалась: разрешение было объявлено, но не запрошено).
- **В списке обхода видны имена сервисов, а не голые CIDR.** Экран «Обходы»
  подписывает подсети (`vk.com`, `RuTube` и т. п.), а не показывает только
  `87.240.129.0/24`.
- **Заголовок и back на экране обхода** стоят правильно после правки размещения.
- **Форма своего обхода поднимается над клавиатурой.** Поля и кнопка «Добавить»
  больше не прячутся под soft-клавиатурой (добавлен `imePadding`).
- **Вход доходит до бота.** Кнопка «Открыть Telegram ещё раз» открывает бота
  входа, а не SUPPORT-бота.

## Проверено на сервере

Проверки через `curl` с рабочей станции, по живому серверу.

- **`GET /api/v1/app/latest?platform=android`** → `{"version":102,"apk_url":"…/app/vpn-102.apk"}`.
- **`GET /api/v1/app/min-supported`** → `102` (поднято с 90 осознанно).
- **`GET /api/v1/app/bypass-routes?platform=android`** → объект с ключами `routes`
  (37 подсетей, для старых клиентов) и `entries` (37 записей вида
  `{"cidr":"109.238.90.0/24","label":"RuTube"}`).
- **`GET /api/v1/app/bypass-services`** → 14 сервисов
  (`max, vk, yandex, ozon, wildberries, avito, mailru, rutube, dzen, kinopoisk,
  sber, tinkoff, gosuslugi, ria`) с `key`/`title`/`domains`.
- **Подписи в `bypass-routes.txt`** — комментарий `# <имя>` над каждой строкой
  `route … net_gateway`; читаются через `entries`.
- **`POST /api/v1/app/bypass/resolve` без токена** → `401`. С реальным токеном
  сессии — резолв доменов/CIDR в подсети `/24`, отказ на всё шире `/8`.
- **`POST /api/v1/app/bypass/set` без токена** → `401`. С токеном — атомарная
  перезапись `app_feed/bypass-routes.txt` с резервной копией; **плохая запись
  отклоняет запрос целиком**, частичных записей нет.
- **`GET /app`** → `200` (HTML-страница загрузки).
- **`GET /app/vpn-102.apk`** отдаётся с `Accept-Ranges: bytes` и отвечает `206`
  на `Range: bytes=0-99` (`Content-Range: bytes 0-99/106707635`), то есть докачка
  работает.

## НЕ проверено

- **`excludeRoute` на устройстве.** Что механизм действительно уводит трафик с
  `tun0`, а не только принимается билдером, ни разу не подтверждено на телефоне.
  Весь механизм обхода РФ-сервисов стоит на этом звене — оно непроверено.
- **UI-путь добавления своего обхода с именем.** Автоматизация soft-клавиатуры на
  телефоне работала ненадёжно, поэтому пишущий путь доказан **через серверный API
  с реальным токеном сессии**, а не прогоном формы в приложении. Что форма шлёт то
  же самое — не проверено глазами от начала до конца.
- **Android 12 и старше (API 26–32).** Поведение на этих версиях не проверялось:
  там `excludeRoute` отсутствует, и обход должен честно отказывать — но вживую это
  не подтверждено.
- **Раздача изнутри РФ.** Доступность страницы и APK с российского подключения не
  проверялась.

## Почему часть проверок — серверные

Беспроводная отладка телефона (`adb over Wi-Fi`) отваливалась многократно, часто
посреди сценария. Из-за этого часть утверждений о поведении проверена на стороне
сервера (контракт эндпоинтов, порог, раздача), а не прогоном в UI. Серверные
проверки подтверждают контракт, но не заменяют проверку экрана.
