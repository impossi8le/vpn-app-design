## Как обращаться к докам

**1. Код — первоисточник истины.** Так прямо написано в
[аудите контракта](api/2026-10-05-contract-audit.md): «Первоисточник истины — код».
Документ описывает замысел; что реально работает — решает код и зелёный прогон.
Где доки расходятся с кодом — прав код, а документ идёт на правку.

**2. Один факт — один дом.** У каждой сквозной темы есть документ-владелец. Если
факт нужен в другом документе, на него **ссылаются**, а не пересказывают — иначе
копии расходятся (как это уже случилось с лицензией, см. низ):

| Тема | Владелец |
|---|---|
| Инвариант защиты (§6) | [2026-10-02-vpn-app-architecture.md](architecture/2026-10-02-vpn-app-architecture.md) §6 |
| Контракт API (протокол) | [2026-10-02-api-contract.md](architecture/2026-10-02-api-contract.md) |
| Выбор движка и лицензия | [2026-10-03-android-architecture.md](architecture/2026-10-03-android-architecture.md) §0, §4.7 |
| Канал доставки, сборка, подпись | [2026-10-06-signing-and-release.md](architecture/2026-10-06-signing-and-release.md) |
| Актуальный UI | [2026-10-06-implemented-ui-spec.md](design/2026-10-06-implemented-ui-spec.md) |

**3. Три жанра — не путать.** Спека говорит, **что и почему**; план — **какими
заданиями**; прогон в `testing/` — **чем доказано**. Не искать «текущее состояние»
в спеке: спека фиксирует замысел на дату, за реальностью идти в `testing/`, в
`git log` и в код.

**4. Статус в шапке важнее даты в имени файла.** Дата в имени — день написания, а
не «актуально на». Порядок доверия: код и прогон → документ со статусом
«реализовано/проверено» → «на ревью» → историческое.

**5. Документы не переписывают задним числом — дописывают поправку с датой.**
Так уже сделано в [api-wiring-design](superpowers/specs/2026-10-05-api-wiring-design.md)
(«Изменение 2026-10-06: подача защиты снята») и в
[data-requirements](api/2026-10-05-data-requirements.md). Ищите последнюю по дате
поправку, а не первое утверждение.

## Открытый вопрос: лицензия (требует решения владельца)

**`LICENSE` в корне — GPLv2, но из кода это не следует.** Единственный GPLv2-код,
ics-openvpn, в проект **не вендорён**: каталога `android/vendor` нет,
`include(":vendor:ics-openvpn")` закомментирован. Используемые движки — OpenVPN 3
(MPL 2.0) и TunnelKit (GPLv3 с исключением Apple §7), ни один не заражает
приложение.

В архитектуре §0 лицензия записана как «GPLv2 — следствие выбора движка» — это
было верно для **отклонённого** пути с ics-openvpn. Сводить проект под GPLv2
никто не обязан.

**Решение за владельцем:** оставить GPLv2 намеренно, сменить на MIT/Apache (код
приложения открыт, движки не заражают) — или что-то ещё. `LICENSE` до решения не
трогать: смена лицензии опубликованного проекта — необратимое действие.
Расхождение честно отмечено в `android/README.md` §«Лицензия».
