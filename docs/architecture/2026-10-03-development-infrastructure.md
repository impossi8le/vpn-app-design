# Инфраструктура разработки: как собираем и тестируем без Mac

Дата: 2026-10-03
Статус: зафиксировано
Область: среда, инструменты и канал доставки iOS-приложения на этом компьютере.

Связанные документы: `2026-10-02-vpn-app-architecture.md`, `2026-10-02-agent-workstreams.md`, `docs/superpowers/specs/2026-09-30-vpn-app-design.md` §11, §14.

## 1. Проблема

Приложение — iOS (SwiftUI + NetworkExtension + TunnelKit), а рабочая машина — **Windows 11**. Apple не выпускает iOS SDK ни для одной ОС, кроме macOS: `xcodebuild`, `codesign`, `xcrun simctl`, `notarytool` существуют только в составе Xcode. Значит собрать `.ipa` и подписать его на Windows нельзя — не в силу настройки, а в силу отсутствия инструментов.

Симулятор iOS туннели не поднимает в принципе — NetworkExtension работает только на физическом устройстве.

## 2. Решение

**Mac не нужен. Нужен арендованный macOS на время сборки.**

GitHub Actions предоставляет macOS-раннеры с установленным Xcode. **На публичном репозитории минуты macOS бесплатны и без лимита, на любом тарифе.** Репозиторий `impossi8le/vpn-app-design` публичный, исходники приложения по спеке §2 тоже открыты — то есть стоимость CI равна нулю.

Цепочка целиком:

```
Windows (эта машина)          macOS-раннер GitHub Actions         iPhone
─────────────────────         ───────────────────────────         ──────
пишем код, доменные тесты  →  сборка, подпись, .ipa → TestFlight →  установка,
(swift build/test здесь)                                          реальный туннель
```

Ни один шаг не требует личного Mac.

## 3. Что уже работает (проверено)

### 3.1 Swift на Windows

Установлен **Swift 6.4.0** через `winget install Swift.Toolchain` (2026-10-02).

Запуск требует обеих частей PATH и `SDKROOT`, иначе падает «unable to load standard library»:

```bash
export SWIFT_ROOT="/c/Users/motin/AppData/Local/Programs/Swift"
export SDKROOT="$SWIFT_ROOT/Platforms/6.4.0/Windows.platform/Developer/SDKs/Windows.sdk"
export PATH="$SWIFT_ROOT/Toolchains/6.4.0+Asserts/usr/bin:$SWIFT_ROOT/Runtimes/6.4.0/usr/bin:$PATH"
```

Предупреждения про `_Builtin_stddef` / `SwiftShims` / `wchar_t` — шум Windows-SDK, не ошибки нашего кода.

**Что собирается здесь:** чистые SPM-пакеты на Foundation. W0 (`CoreDomain`, `TestSupport`, `TestSupportMockBackend`) прошёл на этой машине — 16/16 тестов, 0 падений.

**Что здесь не собирается:** iOS-таргеты, NetworkExtension, симулятор, TunnelKit в NE-таргете. Это требует macOS.

### 3.2 CI на GitHub Actions

Файл `.github/workflows/ios.yml`. Прогон на коммите `f753f09` — **success**.

Три job'а:

| Job | Раннер | Что делает | Состояние |
|---|---|---|---|
| `packages` | `macos-15` | собирает и тестирует все SPM-пакеты | **работает** |
| `detect` | `ubuntu-latest` | проверяет, появился ли app-проект | **работает** |
| `build` | `macos-15` | archive → `.ipa` → TestFlight | пропускается, пока нет app-таргета |

`detect` нужен потому, что `hashFiles()` доступен только внутри `steps`, не в job-level `if`. Первая версия workflow из-за этого падала с нулём job'ов — исправлено.

## 4. Что нужно от человека

**1. Apple Developer Program — $99/год.** Единственный обязательный платёж, обойти нельзя:
- бесплатный Apple ID даёт сборки на 7 дней, но только через Xcode на Mac — не наш путь;
- TestFlight доступен только платным участникам;
- энтайтлмент `packet-tunnel-provider` без платного аккаунта не оформить.

По спеке §2 — зарубежный Apple ID, физлицо, не связанный с РФ.

**2. Браузер.** Всё, что раньше делалось в Xcode, делается в веб-кабинете Apple Developer:
- App ID с включённым Network Extension;
- сертификат подписи;
- provisioning profiles — **отдельный для расширения**;
- сложить сертификат и профили в GitHub Secrets.

Делается один раз.

**3. Больше ничего.** Второй телефон не нужен, Mac не нужен.

## 5. Подпись расширения — место, где будет больно

Не потому что нужен Mac, а потому что конфигурация капризная. Три задокументированные ловушки:

1. **`exportOptions.plist` требует запись `provisioningProfiles` для КАЖДОГО bundle id, включая расширение.** Пропущенное расширение — самая частая причина ошибки «wrong profile type» именно в CI: локально Xcode разрешает профиль сам, в CI разрешать нечем.
2. **Автоподпись гасить в каждом таргете отдельно** (`CODE_SIGN_STYLE=Manual`), не на уровне проекта — иначе расширение молча уезжает на development-профиль.
3. **Рассинхрон энтайтлмента:** профиль разрешает `packet-tunnel-provider-systemextension`, а Xcode генерирует `packet-tunnel-provider`; AMFI это отвергает. Задокументированная головная боль, у людей уходят дни.

Заготовка `exportOptions.plist` лежит в репо с комментариями об этих ловушках. Заполняется на W6/W9.

## 6. Что из этого следует для плана работ

- **Потоки W0–W3, W5, W7** (домен, сеть, состояние, UI-логика) пишутся и тестируются здесь — Swift на Windows их покрывает.
- **W4** (линковка TunnelKit в NE-таргет) — часть проверки только на macOS-раннере.
- **W6** (расширение) и **W9** (реальный туннель) — только macOS-раннер плюс физический iPhone.
- **W8** (CI) — фактически уже сделан в объёме, который возможен без app-таргета; дополняется подписью на W6/W9.

## 7. Риски

| Риск | Митигация |
|---|---|
| TestFlight-сборка живёт 90 дней | CI пересобирает по расписанию; ручная пересборка не выживет (спека §11) |
| Настройка подписи съест дни | Ловушки выше зафиксированы заранее; делать на W6, не в конце |
| Допустимость TestFlight по 5.4 не подтверждена | Держать план на случай отказа Beta App Review (спека §11) |
| Windows-сборка домена разойдётся с macOS | Один и тот же CI гоняет тесты на macOS на каждый push — расхождение видно сразу |

## 8. Открытые вопросы

1. **Публичный ли должен быть репозиторий кода** (не дизайна). Если код будет приватным — macOS-минуты перестают быть бесплатными: 2000 минут ÷ 10 = ~200 macOS-минут в месяц. При 8–12 минутах на сборку это ~20 сборок, для старта хватает, но запас невелик.
2. **Организация или физлицо** в Apple Developer — по спеке физлицо, но 5.4 требует публикацию организацией. Влияет на канал раздачи, не на сборку.
