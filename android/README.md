# Android-клиент — каркас проекта

Каркас многомодульного Gradle-проекта. Соответствует
`docs/architecture/2026-10-03-android-architecture.md`.

**Это каркас, а не работающее приложение.** Ни один модуль пока не содержит
реализации — только структуру и зафиксированные зависимости.

**Про ядро (решение 2026-10-04).** Исходный план «вендорить ics-openvpn» не
работает: это `android.application`, а не библиотека (в README прямо сказано,
что библиотеку делать не собираются); JitPack публикует APK, а не AAR; из
пятнадцати самых звёздных форков ни один не выделил библиотеку. AAR
`co.pango:openvpn-aar` оказался пустой оболочкой (`classes.jar` — 22 байта) с
незаявленной лицензией при GPLv2-ядре внутри. Выбран **OpenVPN 3**: MPL 2.0 не
заражает приложение, проект официальный и сопровождаемый, а OpenVPN Connect под
Android собран именно так. Мост пишем сами; перед кодом — проверка сборки под
arm64, парсинга боевого `.ovpn` и генерации биндинга.

**Приложение запускается и показывает главный экран**, но подключение не работает:
движок VPN не подключён, и заглушка честно отвечает отказом с причиной, а не
изображает успех. Экран при этом показывает «защита не подтверждена» — это правда.

CI на 2026-10-03: юнит-тесты (225), инструментальные на эмуляторе (9 тестов реально
выполняются), подписанный релиз. Все зелёные.

**Отдельно про инструментальные тесты:** в них НЕЛЬЗЯ использовать backtick-имена
методов — D8 до DEX 040 запрещает пробелы в именах, а эти тесты компилируются в
DEX. Только camelCase. В `src/test` (JVM) обратные кавычки работают как обычно.

## Что проверить сборкой

Версии в `gradle/libs.versions.toml` зафиксированы, но **не проверены прогоном**:
на рабочей машине нет JDK и Android SDK, и локальный тулчейн ставить не планируется
(§10.1 архитектуры). Первый прогон CI обязан подтвердить совместимость
AGP / Kotlin / Compose / Gradle.

## Как получить APK и поставить на телефон

**Автоматически (рекомендуется)** — скрипт сам скачает последний debug-APK из
GitHub Actions, поставит его и проверит, что приложение запустилось:

```bash
scripts/install-apk.sh
```

**Вручную:**

1. Откройте **https://github.com/impossi8le/vpn-app-design/actions** и выберите
   последний зелёный прогон **Android**.
2. Внизу страницы прогона, в разделе **Artifacts**, скачайте
   `vpn-app-debug-<номер>` — это zip.
3. Распакуйте zip: внутри `app-debug.apk`.
4. Перекиньте APK на телефон и установите. Android попросит разрешить установку
   из неизвестных источников — это ожидаемо, приложение раздаётся в обход
   магазинов.
5. Если стоит предыдущая версия, номер сборки растёт сам, и APK встанет поверх.

**Для скрипта нужен только `adb`** — JDK, Android SDK и Gradle не требуются.
`adb` берётся из `.tools/platform-tools/` (скачивается один раз вручную) или из
`PATH`. На телефоне надо включить отладку по USB.

**Что приложение делает сейчас, честно:** запускается и показывает главный экран,
но подключиться не может — движок VPN не подключён (§4.7). На попытку
подключения оно отвечает причиной, а не имитацией работы. Экран при этом
показывает «защита не подтверждена» — это правда, а не ошибка.


## Локальный запуск на эмуляторе

Тулчейн есть локально: SDK в `.tools/sdk` (поставлен через `cmdline-tools`),
JDK — из `D:\AndroidStudio\jbr`.

```bash
scripts/run-emulator.sh
```

Скрипт создаёт AVD `vpnapp-api35` при отсутствии, поднимает эмулятор, ждёт
`sys.boot_completed` (а не только появления устройства — установка на ещё не
поднятую систему падает) и ставит последний APK из CI.

**Что приложение делает сейчас, проверено на эмуляторе:** запускается, показывает
главный экран «Отключено / Трафик идёт напрямую», а на нажатие «Подключить»
отвечает **«Не удалось подключиться: способ встраивания ядра OpenVPN не выбран»**.
Это осознанный честный отказ: приложение не изображает работающий VPN.
Скриншот: `docs/testing/2026-10-04-emulator-honest-refusal.png`.

## Сборка — только через GitHub Actions

Локально не собирается и не тестируется: JDK, Gradle и Android SDK на машине нет.
**Ни один код не считается проверенным, пока не прошёл CI.**

Workflow `Android` на `ubuntu-latest` сам ставит JDK 17, Android SDK и Gradle 8.11.1.
Запускается на push в `main` и на PR, если затронут `android/` или сам workflow.

```bash
gh run watch
```

## Что сделать первым, когда CI заработает

1. ~~**Сгенерировать Gradle wrapper**~~ — сделано: wrapper в репозитории, пришпилен к 8.11.1.
2. **Убедиться, что тесты действительно выполняются.** Два теста этого не простят:
   задача `testDebugUnitTest` их не видит (нет в JVM-модулях), а JUnit5 в Android-модулях
   без `useJUnitPlatform()` даёт ноль тестов при зелёной сборке. Оба случая закрыты,
   плюс в CI есть шаг проверки числа выполненных тестов.
3. **Добавить эмулятор в CI** (`reactivecircus/android-emulator-runner`), когда
   дойдёт до потока WA6 — без него честность пробы защиты §6 непроверяема.

## Границы модулей

Стрелка = «зависит от». Нарушение направления — ошибка проектирования.

```
:app
 ├─ :feature:auth  :feature:home  :feature:configs  :feature:account
 │    └─ :core:domain, :core:ui
 ├─ :core:network  :core:config  :core:security  :core:tunnel  :core:protection
 │    └─ :core:domain
 └─ :vpnservice ─── :core:config + vendor:ics-openvpn (JNI)
```

`core:domain`, `core:config`, `core:network` — **чистый Kotlin/JVM**: тесты идут
без эмулятора. Остальные `core:*` — Android-библиотеки.

## Порядок дальнейшей работы

Потоки `WA0…WA9` описаны в §5 архитектурного документа.
`WA0` (интерфейсы + фейки) обязан смержиться первым — он разблокирует остальные.

Первый шаг перед любым кодом: **сгенерировать Gradle wrapper и прогнать сборку**,
чтобы убедиться, что каркас вообще компилируется.
